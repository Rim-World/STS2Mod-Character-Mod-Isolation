# Character Mod Isolation / 角色模组隔离

让第三方角色模组保持启用，同时在游玩原版角色时把角色模组新增的内容从本局内容池中隔离。纯卡牌、纯遗物等非角色模组内容继续出现。

- 当前版本：0.2.0。状态：可构建；0.113.1 完整原版角色局 victory；0.111.1 飞溅专项完整局 49 层上限放弃、退出码 0，58 次飞溅均 0 模组；两版分类覆盖 0 残留。
- 目标游戏：Slay the Spire 2 0.111.1、0.113.1。0.107.1 停止支持；精确 0.111.0 不单独复测。
- 运行环境：Godot 4.5.1、.NET 9、Harmony。
- 设计文档：[可行性调研](../3.DOCS/001-R-角色模组隔离可行性调研.md)、[总体设计](../5.SDD/001-总体设计草案.md)、[隔离行为规范](../6.SPEC/001-隔离行为规范-v0.5.md)。

## 它解决什么

安装角色模组后，原版角色局可能出现该模组的卡牌、遗物、药水、事件、遭遇、先古与章节。「飞溅」等跨角色效果尤其明显：它会从全部已解锁角色卡池里挑牌。

本模组不卸载、不禁用角色模组。它在每局开始时判断：

- 本局角色全部是原版角色：只过滤被判定为角色模组的模组内容。
- 本局有模组角色：不过滤。
- 非角色模组：自动模式不隔离；手动模式下按勾选集合处理。
- 不在局内：不过滤。
- 多人：默认不过滤。

## 工作方式

自动模式先识别角色模组；手动模式完全跳过识别，只使用勾选集合。之后执行同一套内容过滤：

1. **角色集合**：局内从 `UnlockState.Characters` 移除角色模组角色，跨角色效果只看到原版卡池。
2. **池查询**：卡牌在 `AllCards` 源数组与 `GetUnlockedCards` 查询出口移除角色模组内容；角色模组池返回空。遗物、药水查询出口同样过滤。
3. **章节内容**：遭遇、事件、先古、章节列表移除角色模组内容，并在事件消费端兜底。
4. **Orobas**：Sea Glass 选项读取角色列表时，使用局部作用域过滤，不修改全局缓存。

归属判断按「模型类型所在程序集 → 已加载模组」映射，不依赖具体模组 ID。未知归属不自动隔离。

## 依赖

依赖 RitsuLib **最新版**，用于设置页、持久化、本地化与加载顺序。运行时还需要 RitsuLib 的完整变体包，不能只复制根 DLL。清单中的 `min_version` 是发布时的最低门槛，不是固定目标；每次构建/发布前必须检查本机已安装版本，并更新到当前最新版。

### 依赖版本检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 9.SRC/tools/check-ritsu-version.ps1
```

- 已安装版本低于清单下限：检查失败，先更新 RitsuLib。
- 已安装版本高于清单下限：提示更新 `min_version` 并重新测试。
- 脚本只读取本机已安装的 RitsuLib，不联网，不修改文件。

## 单 DLL 兼容

- 一个项目、一个程序集、一个 `mod_manifest.json`；不按游戏版本生成两个包。
- `RitsuLibCompatTarget=0.111.0` 是 RitsuLib 包内的兼容分支，不是游戏版本，也不是第二份模组。
- 编译引用当前游戏程序集；运行时由同一份 DLL 调用 0.111/0.113 的共同成员。差异目标由补丁注册器按存在性选择。
- 已验证：同一 SHA-256 的 DLL 在 0.111.1 与 0.113.1 均加载并完成 AutoSlayer；详见 [013-E](../3.DOCS/013-E-同一DLL跨版本验证.md)。

## 安装

```text
Slay the Spire 2/mods/CharacterModIsolation/
├── CharacterModIsolation.dll
└── mod_manifest.json
```

本地化 JSON 嵌入程序集，不需要单独的 `localization/` 目录。

## 设置

设置页由 RitsuLib 提供，主菜单和暂停菜单都可打开。

- 总开关：默认开。
- 卡牌、遗物、药水、事件、遭遇、先古、章节：默认开。
- 隔离来源：自动识别 / 手动选择，二选一。
- 自动识别：只显示已启用且被识别为角色模组的模组，包含名称、ID、分类、依据与本局过滤状态；可重新检测。
- 手动选择：只列出已启用模组并允许勾选；只隔离勾选项；不启动自动识别；空集合不隔离。
- 详细日志：默认关。
- 设置改动下一局生效；当前局保持开局判定。

## 构建

```bash
dotnet build 9.SRC/CharacterModIsolation.csproj -c Release
```

默认引用本机当前游戏版本的 `sts2.dll`、`0Harmony.dll` 和已安装的 RitsuLib 变体包。测试环境为 0.111.1、0.113.1；兼容编译入口为 0.111.0。换机器时用 `/p:Sts2Dir=...`、`/p:RitsuLibDeployRoot=...` 覆盖。

构建前先运行上面的依赖版本检查。若检查提示 RitsuLib 比清单新，更新 `min_version` 后再构建和复测，不要把旧下限当成固定目标。

## 已知限制

- 不隔离角色模组对原版代码的直接 Harmony 补丁。
- 不清理已有存档中的模组内容；只影响之后新生成的内容。
- 不隐藏图鉴、卡牌库中的模组条目。
- 多人默认跳过，不提供开启开关。
- 选人界面选择「随机角色」时，随机结果可能是角色模组角色；该局按模组角色处理，不隔离。
- 角色模组识别可能失败或误判；未知模组默认不隔离，可切换到手动选择。
- 自动模式与手动模式互斥，不提供自动结果上的逐模组例外。
- 0.111.1 飞溅专项完整局到 49 层上限后由 AutoSlayer 主动放弃，不是胜利；0.113.1 完整局为 victory。两版均已跑完流程并核对分类覆盖。
- 「飞溅」已实际出牌验证；其他跨角色效果未逐个实机出牌，共用 `AllCards` / `GetUnlockedCards` 过滤出口。

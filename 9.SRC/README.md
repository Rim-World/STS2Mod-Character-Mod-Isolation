# Character Mod Isolation / 角色模组隔离

让第三方角色模组保持启用，同时在游玩原版角色时把角色模组新增的内容从本局内容池中隔离。纯卡牌、纯遗物等非角色模组内容继续出现。

- 状态：可构建；0.113.1 无头加载、色彩哲学家场景与 AutoSlayer 全跑通过。下一版本兼容 0.111.0、0.113.1，施工计划见 [009-M](../2.PLANS/009-M-111兼容与检测显示.md)。
- 目标游戏：Slay the Spire 2 0.107.1、0.111.0、0.113.1（当前实现）。下一版本目标为 0.111.0、0.113.1；0.107.1 停止支持，见 [009-M](../2.PLANS/009-M-111兼容与检测显示.md)。
- 运行环境：Godot 4.5.1、.NET 9、Harmony。
- 设计文档：[可行性调研](../3.DOCS/001-R-角色模组隔离可行性调研.md)、[总体设计](../5.SDD/001-总体设计草案.md)、[隔离行为规范](../6.SPEC/001-隔离行为规范-v0.4.md)。

## 它解决什么

安装角色模组后，原版角色局可能出现该模组的卡牌、遗物、药水、事件、遭遇、先古与章节。「飞溅」等跨角色效果尤其明显：它会从全部已解锁角色卡池里挑牌。

本模组不卸载、不禁用角色模组。它在每局开始时判断：

- 本局角色全部是原版角色：只过滤被判定为角色模组的模组内容。
- 本局有模组角色：不过滤。
- 非角色模组：自动模式不隔离；手动模式下按勾选集合处理。
- 不在局内：不过滤。
- 多人：默认不过滤。

## 工作方式

自动模式先识别角色模组；手动模式完全跳过识别，只使用勾选集合。之后执行同一套内容过滤：

1. **角色集合**：局内从 `UnlockState.Characters` 移除角色模组角色，跨角色效果只看到原版卡池。
2. **池查询**：卡牌、遗物、药水查询出口移除角色模组内容；角色模组池返回空。
3. **章节内容**：遭遇、事件、先古、章节列表移除角色模组内容，并在事件消费端兜底。
4. **Orobas**：Sea Glass 选项读取角色列表时，使用局部作用域过滤，不修改全局缓存。

归属判断按「模型类型所在程序集 → 已加载模组」映射，不依赖具体模组 ID。未知归属不自动隔离。

## 依赖

依赖 RitsuLib 0.6.13 或更高，用于设置页、持久化、本地化与加载顺序。运行时还需要 RitsuLib 的完整变体包，不能只复制根 DLL。

## 安装

```text
Slay the Spire 2/mods/CharacterModIsolation/
├── CharacterModIsolation.dll
└── mod_manifest.json
```

本地化 JSON 嵌入程序集，不需要单独的 `localization/` 目录。

## 设置

设置页由 RitsuLib 提供，主菜单和暂停菜单都可打开。

- 总开关：默认开。
- 卡牌、遗物、药水、事件、遭遇、先古、章节：默认开。
- 隔离来源：自动识别 / 手动选择，二选一。
- 自动识别：显示每个已加载模组的分类与依据；可重新检测。
- 手动选择：列出已加载模组并允许勾选；只隔离勾选项；不启动自动识别；空集合不隔离。
- 详细日志：默认关。
- 设置改动下一局生效；当前局保持开局判定。

## 构建

```bash
dotnet build 9.SRC/CharacterModIsolation.csproj -c Release
```

默认引用本机 0.113.1 的 `sts2.dll`、`0Harmony.dll` 和已安装的 RitsuLib 变体包。换机器时用 `/p:Sts2Dir=...`、`/p:RitsuLibDeployRoot=...` 覆盖。

## 已知限制

- 不隔离角色模组对原版代码的直接 Harmony 补丁。
- 不清理已有存档中的模组内容；只影响之后新生成的内容。
- 不隐藏图鉴、卡牌库中的模组条目。
- 多人默认跳过，不提供开启开关。
- 选人界面选择「随机角色」时，随机结果可能是角色模组角色；该局按模组角色处理，不隔离。
- 角色模组识别可能失败或误判；未知模组默认不隔离，可切换到手动选择。
- 自动模式与手动模式互斥，不提供自动结果上的逐模组例外。

# Character Mod Isolation / 角色模组隔离

让第三方角色模组保持启用，同时在游玩原版角色时隔离全部角色模组新增内容；在游玩角色模组角色时只保护当前角色所属模组，隔离其他角色模组。纯卡牌、纯遗物等非角色模组内容继续出现。

- 当前版本：0.3.0。状态：0.111.1 与 0.113.1 的自动保护集、两局缓存通过；0.111.1 自动原版推进到 49 层上限，0.113.1 自动原版 49 层 victory；最终 DLL 已在 0.111.1 加载并复跑自动 MGR。MGR 完整局仍受 MGR 自身异常影响。
- 目标游戏：Slay the Spire 2 0.111.1、0.113.1。0.107.1 停止支持；精确 0.111.0 不单独复测。
- 运行环境：Godot 4.5.1、.NET 9、Harmony。
- 设计文档：[可行性调研](../3.DOCS/001-R-角色模组隔离可行性调研.md)、[总体设计](../5.SDD/001-总体设计草案.md)、[隔离行为规范 v0.6](../6.SPEC/001-隔离行为规范-v0.6.md)。

## 它解决什么

安装角色模组后，原版角色局可能出现该模组的卡牌、遗物、药水、事件、遭遇、先古与章节。「飞溅」等跨角色效果尤其明显：它会从全部已解锁角色卡池里挑牌。

本模组不卸载、不禁用角色模组。它在每局开始时判断：

- 本局角色是原版角色：隔离全部角色模组内容。
- 本局角色来自角色模组 A：保护 A 的卡牌、遗物、药水、开局牌组与角色；隔离其他角色模组。
- 非角色模组：自动模式不隔离；手动模式下只有勾选模组被视为角色模组。
- 隔离集为空：不过滤；当前角色内容保留。
- 不在局内：不过滤。
- 多人：默认不过滤。

## 工作方式

自动模式先识别角色模组；手动模式跳过识别，把勾选模组视为角色模组。两种模式都计算保护集 `P` 与隔离集 `I`：当前角色所属模组进入 `P`，角色模组集合减去 `P` 得到 `I`。之后执行同一套内容过滤：

1. **角色集合**：局内从 `UnlockState.Characters` 移除 `I` 中的角色；当前角色所属模组与原版角色保留。
2. **池查询**：卡牌在 `AllCards` 源数组与 `GetUnlockedCards` 查询出口移除 `I` 中的内容；`I` 中的角色模组池返回空。遗物、药水查询出口同样过滤。
3. **章节内容**：遭遇、事件、先古、章节列表移除 `I` 中的内容，并在事件消费端兜底。
4. **Orobas**：Sea Glass 选项读取角色列表时，使用局部作用域过滤，不修改全局缓存。
5. **缓存**：卡池源过滤缓存按原始策略纪元 `PolicyEpoch` 与设置版本失效；同一进程换局时重建。热路径不读取会刷新运行上下文的 `PolicyVersion`。

归属判断按「模型类型所在程序集 → 已加载模组」映射，不依赖具体模组 ID。未知归属不自动隔离。

## 依赖

依赖 RitsuLib **最新版**，用于设置页、持久化、本地化与加载顺序。运行时还需要 RitsuLib 的完整变体包，不能只复制根 DLL。清单中的 `min_version` 是发布时的最低门槛，不是固定目标；每次构建/发布前必须检查本机已安装版本，并更新到当前最新版。

### 依赖版本检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 9.SRC/tools/check-ritsu-version.ps1
```

- 已安装版本低于清单下限：检查失败，先更新 RitsuLib。
- 已安装版本高于清单下限：提示更新 `min_version` 并重新测试。
- 脚本只读取本机已安装的 RitsuLib，不联网，不修改文件。

## 单 DLL 兼容

- 一个项目、一个程序集、一个 `mod_manifest.json`；不按游戏版本生成两个包。
- `RitsuLibCompatTarget=0.111.0` 是 RitsuLib 包内的兼容分支，不是游戏版本，也不是第二份模组。
- 编译引用当前游戏程序集；运行时由同一份 DLL 调用 0.111/0.113 的共同成员。差异目标由补丁注册器按存在性选择。
- 0.2.0 历史验证：同一 SHA-256 的 DLL 在 0.111.1 与 0.113.1 均加载并完成 AutoSlayer。0.3.0 的 0.111.1 最终 DLL 加载、自动 MGR 与两局缓存通过；0.113.1 的 Watcher 与原版完整局通过。详见 [013-E](../3.DOCS/013-E-同一DLL跨版本验证.md) 与 [021-E](../3.DOCS/021-E-P1保护集与缓存验证.md)。

## 安装

```text
Slay the Spire 2/mods/CharacterModIsolation/
├── CharacterModIsolation.dll
└── mod_manifest.json
```

本地化 JSON 嵌入程序集，不需要单独的 `localization/` 目录。

## 设置

设置页由 RitsuLib 提供，主菜单和暂停菜单都可打开。

- 总开关：默认开。
- 卡牌、遗物、药水、事件、遭遇、先古、章节：默认开。
- 隔离来源：自动识别 / 手动选择，二选一。
- 自动识别：只显示已启用且被识别为角色模组的模组，包含名称、ID、分类、依据与本局状态；可重新检测。
- 手动选择：只列出已启用模组并允许勾选；勾选模组被视为角色模组；当前角色所属模组受保护，其他勾选模组被隔离；空集合不隔离。
- 详细日志：默认关。
- 设置改动下一局生效；当前局保持开局判定。

## 构建

```bash
dotnet build 9.SRC/CharacterModIsolation.csproj -c Release
```

默认引用本机当前游戏版本的 `sts2.dll`、`0Harmony.dll` 和已安装的 RitsuLib 变体包。测试环境为 0.111.1、0.113.1；兼容编译入口为 0.111.0。换机器时用 `/p:Sts2Dir=...`、`/p:RitsuLibDeployRoot=...` 覆盖。

构建前先运行上面的依赖版本检查。若检查提示 RitsuLib 比清单新，更新 `min_version` 后再构建和复测，不要把旧下限当成固定目标。

## 已知限制

- 不隔离角色模组对原版代码的直接 Harmony 补丁。
- 不清理已有存档中的模组内容；只影响之后新生成的内容。
- 不隐藏图鉴、卡牌库中的模组条目。
- 多人默认跳过，不提供开启开关。
- 选人界面选择「随机角色」时，随机结果可能是角色模组角色；该局按模组角色处理，不隔离。
- 角色模组识别可能失败或误判；未知模组默认不隔离，可切换到手动选择。
- 自动模式与手动模式互斥，不提供自动结果上的逐模组例外。
- 0.111.1 与 0.113.1 的 P4 特殊路径只运行约 155 秒，不是完整三幕;0.113.1 的 0.3.0 完整原版局为 49 层 victory。
- MGR 0.8.1 的 `ShowChanneledNote` 在 0.111.1 与 0.113.1 都会越界；CMI 不对其打补丁。
- 设置页视觉、选人界面、旧存档、多人、随机角色尚未完成 0.3.0 人工验收。
- 色彩哲学家只验证选项生成，未点击奖励并检查奖励牌。
- 直接读取 `ModelDb` 全局集合仍可能看到其他角色模组内容；池过滤通过不等于全局读取隔离。

# 005 多人模式默认不启用

- 状态：已接受
- 日期：2026-11-17
- 当时项目版本：0.0.0（仅调研）
- 相关文件：[隔离行为规范](../6.SPEC/001-隔离行为规范-v0.4.md)、[方案对比与风险](../3.DOCS/005-R-方案对比与风险.md)

## 背景

隔离会改变候选内容与随机数消耗。多人模式要求各端状态一致；模组设置存在本地，未同步。若一名玩家开启隔离、另一名关闭，候选与随机序列可能分叉，导致状态不同步。

## 决策

多人会话默认不启用隔离，即使总开关为开。日志写明跳过原因。提供显式 `multiplayer_enabled` 开关，默认 false；开启时在设置页提示所有玩家必须使用相同配置与模组集合。v1 不实现配置同步。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 默认开启 | 配置不一致时状态发散风险高 |
| 按玩家分别过滤 | 奖励/事件是共享或跨玩家，无法完全隔离 |
| 主机下发配置 | 需要网络消息与协议版本，v1 成本高 |
| 禁止多人使用 | 过度限制；默认关闭已足够 |

## 后果

**获益**

- 避免最严重的多人不同步。
- 单机体验不受影响。

**代价**

- 多人玩家无法享受隔离；需要显式开启并自行保证配置一致。
- 未来若做同步，需要新增协议与版本校验。

**下游规则**

1. 多人判定读取 `RunManager.NetService.Type`，不是只看玩家数量。
2. 跳过时 Info 日志写明网络类型。
3. 设置页对多人开关显示风险说明。
4. 不在局内改变隔离判定；设置变更只影响下一局。

# 004 过滤在池查询与内容消费两端布防

- 状态：提议
- 日期：2026-11-17
- 当时项目版本：0.0.0（仅调研）
- 相关文件：[内容注册与生成链路](../3.DOCS/002-E-游戏内容注册与生成链路取证.md)、[过滤补丁族](../2.PLANS/004-M-过滤补丁族.md)

## 背景

模组内容可以通过多种方式进入局内：池拼接、BaseLib/RitsuLib 的 Harmony 后置、章节事件列表、先古共享子集、直接奖励注入。只在池查询出口过滤，可能漏掉后置追加；只在消费端过滤，可能改变随机数顺序或漏掉其他消费者。

## 决策

两层布防：

1. **源过滤**：在内容列表/池查询出口过滤，尽量让角色模组内容不进入候选。包括 `UnlockState.Characters`、`GetUnlockedCards/Relics/Potions`、`AllEncounters` 及其弱/普通/精英/Boss/怪物派生 getter、`AllSharedEvents`、具体章节的 `AllEvents/AllAncients/GetUnlockedAncients`、`AllSharedAncients`、`ActsByIndex`、`GenerateRooms` 前置清理。
2. **消费端兜底**：在 `ActModel.PullNextEvent` 前置移除残留模组事件；可选在 `CardCreationOptions.GetPossibleCards` 与 `CardFactory` 出口再过滤。

补丁顺序：核心过滤使用 `HarmonyAfter("BaseLib", "STS2-RitsuLib")` 与 `Priority.Last`；事件消费端兜底不依赖顺序。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 重写 `Splash.OnPlay` | 版本敏感；只覆盖一张牌 |
| 直接修改池缓存 | 影响全局模型库与存档；不可逆 |
| 只做消费端过滤 | 随机数顺序已被角色模组内容影响；覆盖不全 |
| 只做源过滤 | 后置追加可能漏；无兜底 |

## 后果

**获益**

- 覆盖池、章节、事件、先古与跨角色效果；有兜底。
- 不改内容池缓存，不改已有存档。

**代价**

- 补丁点较多，需要顺序与失败隔离。
- 事件消费端移除可能改变事件顺序；只作为兜底。
- 可选严格模式可能减少候选数量。

**下游规则**

1. 过滤器必须幂等；重复调用结果一致。
2. 过滤不得修改原列表对象；返回新列表或移除副本。
3. 任何过滤异常返回原结果。
4. 补丁失败按类别关闭；核心失败整体关闭。
5. 运行日志必须能看出每个类别移除了多少。

# 002 单程序集兼容三版本

- 状态：被 ADR-009 取代（仅兼容范围）
- 日期：2026-11-17
- 当时项目版本：0.0.0（仅调研）
- 相关文件：[三版本 API 对照](../3.DOCS/003-E-三版本API对照.md)、[交付形态计划](../2.PLANS/007-S-打包与发布.md)

## 背景

用户要求兼容 0.107.1、0.111.0、0.113.1。本机只有 0.113.1 的 `sts2.dll`；旧版只有反编译源码，没有可引用程序集。项目需要读取模组列表、本局角色、卡池与章节内容。部分成员三版有差异：`Mod.assembly` 与 `Mod.assemblies`、`ModelDb.AllCharacters` 数量、`ActModel.GenerateRooms` 重载、`GameMode` 新枚举值。

## 决策

一个程序集、一个目录、一个清单，同时服务三版。编译基线为 0.113.1 的 `sts2.dll`；运行期只调用 [003-E](../3.DOCS/003-E-三版本API对照.md) 表中签名一致的成员；差异成员用反射。`min_game_version` 写 `0.107.1`。不写根加载器，不拆变体目录。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 三份构建 + 根加载器 | 用户要一份安装；加载器要版本探测与模块校验；补丁面不值得 |
| 用 0.107.1 编译 | 本机没有旧版程序集 |
| 只支持 0.113.1 | 与 RQ-009 冲突 |
| 所有成员反射探测 | 热路径开销大、失败面大；已知差异只需两处反射 |

## 后果

**获益**

- 玩家只装一个目录；发布与测试一条线。
- 不需要旧版程序集即可编译。

**代价**

- 编译器不能阻止引用新版专属成员；靠 API 白名单与人工比对。
- 旧版运行行为未实测；需要旧版环境回归。
- 未来若关键成员改签名，单包会同时影响三版。

**下游规则**

1. 新增运行期成员前，先补进 003-E 并核对三版。
2. 不引用 0.113 专属类型/枚举值/重载。
3. `Mod` 程序集字段只走反射。
4. 章节按版本补丁 `GenerateRooms` 存在的重载；代码不得直接调用该方法。
5. 旧版实测前，发布说明不得声称「已验证」。

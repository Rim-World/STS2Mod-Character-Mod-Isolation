# 003 内容归属按程序集映射

- 状态：提议
- 日期：2026-11-17
- 当时项目版本：0.0.0（仅调研）
- 相关文件：[第三方角色模组取证](../3.DOCS/004-E-第三方角色模组实现方式取证.md)、[总体设计草案](../5.SDD/001-总体设计草案.md)

## 背景

过滤器需要判断一个模型类型是否属于第三方模组。`ModHelper.AddModelToPool` 只记录类型，不记录模组 ID；BaseLib 也没有通用归属表。RitsuLib 有 `ModContentRegistry.TryGetOwnerModId`，但只覆盖用 RitsuLib 注册的内容。角色模组可能使用 BaseLib、RitsuLib 或直接调用 `ModHelper`。

## 决策

以「类型所在程序集」为主归属依据：

1. 遍历 `ModManager.GetLoadedMods()`。
2. 反射读取 `Mod.assemblies`（111+）或 `Mod.assembly`（107）。
3. 建立 `Assembly -> modId`。
4. 未登记程序集用 `Assembly.Location` 是否位于 `Mod.path` 下补充。
5. 仍未知时用根命名空间与模组 ID/名称匹配。
6. 游戏程序集为原版；已知框架程序集为框架；其他非游戏程序集按模组内容归属，但不自动隔离。
7. 类型结果缓存。

RitsuLib 的 `TryGetOwnerModId` 作为可选精确来源，存在时优先。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 解析 ModelId 前缀 | 依赖模组自觉；BaseLib 可能改 ID；不可靠 |
| 只信 RitsuLib 注册表 | 不覆盖 BaseLib/直接注册的模组 |
| 硬编码模组 ID/角色名单 | 每装一个新模组都要改代码 |
| 只按命名空间 | 命名空间可任意写；程序集更稳定 |

## 后果

**获益**

- 对标准注册的角色模组通用；新增模组不需要改代码。
- 不依赖具体框架；RitsuLib 只作增强。

**代价**

- 多个模组共用一个内容程序集时无法细分；按同一归属处理。
- 动态类型、游戏程序集内的类型无法归属。
- 未知程序集默认按模组内容归属，但不自动隔离；需要日志与手动设置。

**下游规则**

1. 归属结果按 `Type` 缓存，不重复遍历程序集。
2. 未知非游戏程序集必须记录一次警告。
3. 框架程序集的辅助类型不参与内容过滤；框架程序集里的具体模型类型按非游戏程序集处理。
4. 归属失败不得抛异常；返回 Unknown，按模组内容归属，但不自动隔离。
5. 内容归属只回答「属于哪个模组」；是否隔离由 ADR-007 的角色模组分类决定。

# 001 按运行角色隔离模组内容

- 状态：提议；ADR-010 提议中，运行策略待替换
- 日期：2026-11-17
- 当时项目版本：0.0.0（仅调研）
- 相关文件：[可行性调研](../3.DOCS/001-R-角色模组隔离可行性调研.md)、[过滤补丁族](../2.PLANS/004-M-过滤补丁族.md)、[隔离行为规范](../6.SPEC/001-隔离行为规范-v0.4.md)

## 背景

游戏启动时加载模组 DLL，DLL 不能卸载；内容池在首次访问后缓存。用户希望角色模组保持启用、选人界面仍可选，但游玩原版角色时不出现该模组新增内容。关模组再重启的做法成本高。

## 决策

不卸载、不禁用模组。按「本局角色集合」建立运行期内容视图：本局所有玩家角色为原版时，只过滤被识别为角色模组的模组新增内容；有模组角色时不隔离。过滤在内容查询出口执行，不改写内容池缓存。角色模组识别见 ADR-007。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 关模组并重启 | 现状；每次切换成本高 |
| 多游戏目录/多配置 | 占空间、更新与存档复杂 |
| 修改加载器按局启用 | DLL 不能卸载；池缓存；不可行 |
| 按当前角色所属模组白名单 | 跨模组内容会断；v1 不做。角色模组识别用自动分类，不按当前角色分组 |

## 后果

**获益**

- 不需要重启；模组角色仍可玩；原版角色局内容干净。
- 过滤只影响内容生成，不删除已有存档。

**代价**

- 不能隔离模组对原版代码的直接补丁。
- 需要处理补丁顺序、多人、旧存档、候选为空等边界。
- 需要维护三版本 API 白名单。

**下游规则**

1. 过滤判定只读本局角色与已加载模组，不读全局 UI 状态。
2. 模组角色局不得过滤。
3. 多人默认不过滤。
4. 过滤失败返回原结果，不抛异常。
5. 不删除、不改写已有存档内容。

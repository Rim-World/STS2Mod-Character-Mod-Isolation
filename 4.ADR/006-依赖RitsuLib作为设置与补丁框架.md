# 006 依赖 RitsuLib 作为设置与补丁框架

- 状态：已接受
- 日期：2026-11-17
- 当时项目版本：0.0.0（仅调研）
- 相关文件：[方案对比与风险](../3.DOCS/005-R-方案对比与风险.md)、[设置页与本地化计划](../2.PLANS/005-S-设置页与本地化.md)

## 背景

隔离核心只需要 Harmony 与游戏 API。但项目还需要：

- 模组设置页与持久化；
- 中英文案；
- 补丁失败降级与日志；
- 三版本兼容的框架支持。

本机与用户环境已安装 RitsuLib（PrismaticGemFilter 依赖它；工坊变体包支持 0.107.1/0.111.0/0.113.1）。BaseLib 偏向内容添加，不提供同等的补丁框架。

## 决策

将 RitsuLib 设为硬依赖，写入 `mod_manifest.json`；用它的设置、持久化、本地化与补丁降级。隔离核心仍用本项目自己的归属与上下文逻辑，不依赖 RitsuLib 的内容注册表作为唯一归属来源。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 只依赖 BaseLib | 无补丁降级框架；设置/持久化需自写 |
| 同时依赖 BaseLib + RitsuLib | 两套设置/存档入口，冲突面大 |
| 不依赖任何库 | 自写设置页、持久化、本地化、降级，维护成本高 |
| 软依赖 RitsuLib | 需要「有/无」两条路径，测试组合翻倍 |

## 后果

**获益**

- 设置页、持久化、本地化、补丁降级直接复用。
- 与用户已有的 PrismaticGemFilter 依赖形态一致。
- RitsuLib 变体包覆盖三版本。

**代价**

- 玩家必须安装 RitsuLib；缺少时本模组不加载。
- 随 RitsuLib 版本节奏更新；其遥测/更新检查需在说明中披露。
- RitsuLib 自身补丁面较大，存在冲突可能。

**下游规则**

1. `mod_manifest.json` 声明 RitsuLib 依赖与最低版本。
2. 不引用 BaseLib 命名空间。
3. 补丁按 RitsuLib 的补丁框架声明；若用户否决依赖，改用自写 Harmony 安装器。
4. 设置键名发布后不改。
5. README 与工坊说明写明依赖与关闭遥测/更新检查的路径。

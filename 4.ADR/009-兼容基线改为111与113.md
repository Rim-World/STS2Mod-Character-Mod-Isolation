# 009 兼容基线改为 0.111 与 0.113

- 状态：已接受
- 日期：2026-11-17 19:35
- 当时项目版本：0.1.0
- 相关文件：[需求范围](../1.PRD/001-项目目标与范围.md)、[兼容需求](../1.PRD/003-非功能与兼容需求.md)、[施工计划](../2.PLANS/009-M-111兼容与检测显示.md)、[ADR-002](002-单程序集兼容三版本.md)

## 背景

项目最初按 0.107.1、0.111.0、0.113.1 三版设计。0.107.1 是较早的测试版本，用户已没有继续使用的需求。0.111.0 已成为正式版本，0.113.1 是本机当前运行版本。

维持 0.107.1 兼容会增加 API 白名单、补丁目标和回归环境的负担。继续把 0.107.1 写进验收标准，会让实际没有验证计划的版本被误认为仍受支持。

## 决策

支持的正式基线只保留 0.111.0 与 0.113.1。0.107.1 不承诺加载、过滤行为或存档兼容，不再列入验收矩阵。施工时更新 `mod_manifest.json` 的 `min_game_version`、README 的目标版本、测试矩阵与兼容性说明。

单程序集交付方式不变。编译基线与运行期 API 白名单在施工前按 0.111.0、0.113.1 的可用程序集重新确认。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 继续兼容三版 | 用户明确放弃 0.107.1；额外 API 差异和回归成本没有收益 |
| 只支持 0.113.1 | 0.111.0 是当前正式版，仍有用户需要 |
| 按版本拆多份 DLL | 用户要求单目录交付；版本探测与维护成本更高 |
| 继续保留 0.107.1 但标“未验证” | 会保留不必要的兼容约束，容易误导发布说明 |

## 后果

**获益**

- 兼容性检查与补丁目标减少一版。
- 发布说明可以明确声明支持范围。
- 0.111.0 的正式版验证成为真实门槛，不再被 0.107 的未完成项阻塞。

**代价**

- 0.107.1 用户不再获得支持。
- 仍需准备 0.111.0 的运行验证环境。
- 旧文档中的三版表述需要逐步清理。

**下游规则**

1. 需求、验收、README、清单与测试计划不得再写“兼容三版”或把 0.107.1 列为目标。
2. 新增运行期成员前，只核对 0.111.0 与 0.113.1。
3. 0.113 专属成员仍不得无条件引用；必须有两版验证或显式版本守卫。
4. 0.107.1 只作为历史记录保留在旧 ADR、旧调研与旧日志中，不作为当前承诺。

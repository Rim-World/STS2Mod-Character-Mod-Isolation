# 008 手动选择模式完全跳过自动识别

- 状态：已接受
- 日期：2026-11-17 03:30
- 当时项目版本：0.0.0（仅调研）
- 相关文件：[ADR-007](007-按已注册角色识别角色模组.md)、[RQ-019](../1.PRD/002-功能需求.md)、[隔离行为规范 v0.4](../6.SPEC/001-隔离行为规范-v0.4.md)、[总体设计草案](../5.SDD/001-总体设计草案.md)、[识别计划](../2.PLANS/008-M-角色模组识别与手动覆盖.md)

## 背景

ADR-007 用逐模组覆盖修正自动识别结果。该方案仍会先执行自动识别，再合并覆盖。

用户明确要求：如果用户选择手动隔离某些模组，本模组自己的角色模组识别不应启动，只屏蔽用户勾选的模组。

这个要求有三个目的：

1. 手动选择是用户明确决定，不应被自动分类干扰。
2. 手动模式不应承担自动识别的成本。
3. 手动模式的行为必须可预测：过滤集合严格等于勾选集合。

## 决策

隔离来源分为两种互斥模式：

1. **自动识别**：默认模式。按 ADR-007 的算法识别角色模组；未知模组默认不隔离。
2. **手动选择**：用户勾选要隔离的模组。进入手动模式后：
   - 不得读取 `ModelDb.AllCharacters` 做角色模组识别；
   - 不得扫描具体 `CharacterModel` 子类；
   - 不得构建自动角色模组分类；
   - 有效隔离集合严格等于勾选集合；
   - 未勾选的模组不得被本模组过滤，即使它有可玩角色；
   - 勾选为空时，不隔离任何内容；
   - 勾选列表持久化，下一局生效。

`ContentOwnership` 在两种模式下都必须运行。它只负责把内容类型映射到模组，不负责判断角色模组。手动模式仍需要它来知道“某张卡属于勾选的哪个模组”。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 保留逐模组覆盖，自动识别后合并 | 用户明确要求手动选择时不要启动自动识别 |
| 只做自动识别，不提供手动模式 | 无法处理自动识别失败或用户明确指定 |
| 只做手动选择 | 每次安装新模组都要手动配置，默认体验差 |
| 手动列表非空时自动切换，列表空时回自动 | 用户取消全部勾选时行为会突然变化，不可预测 |
| 手动模式仍读取 `ModelDb.AllCharacters` 只为日志 | 违背“识别不启动”，也增加启动成本 |

## 后果

**获益**

- 手动模式行为完全由用户控制，不混入自动分类。
- 手动模式跳过角色注册表读取与类型扫描，启动开销更低。
- 自动模式仍保留开箱即用体验。

**代价**

- 两种模式互斥，不能“自动识别 + 排除某一个模组”。需要精确控制时，切换到手动模式并勾选需要的模组。
- 手动模式不会提示某个已勾选模组是否真的包含角色内容；用户需要自己确认。
- 手动模式仍依赖内容归属映射；归属失败的内容无法过滤。

**下游规则**

1. 设置页必须先选模式，再显示对应控件。
2. 手动模式下，`CharacterModRegistry.EnsureBuilt()` 必须直接返回，不读取角色列表、不扫描类型。
3. 手动模式的有效集合只来自持久化的勾选列表。
4. 手动模式勾选为空时，隔离函数必须快速返回原结果。
5. 模式与勾选列表变更只影响下一局。
6. 日志必须写明当前模式、勾选数量；不得输出自动分类结果，因为自动识别没有运行。
7. 自动模式仍遵守 ADR-007；手动模式不读取自动分类。

# 007 按已注册角色识别角色模组

- 状态：已接受；手动覆盖部分被 ADR-008 取代
- 日期：2026-11-17 03:05
- 当时项目版本：0.0.0（仅调研）
- 相关文件：[功能需求 RQ-019](../1.PRD/002-功能需求.md)、[隔离行为规范 v0.4](../6.SPEC/001-隔离行为规范-v0.4.md)、[总体设计草案](../5.SDD/001-总体设计草案.md)、[第三方角色模组取证](../3.DOCS/004-E-第三方角色模组实现方式取证.md)

## 背景

用户要求只隔离「角色模组」的内容，不隔离纯卡牌、纯遗物、纯药水等内容模组。上一版设计把所有非游戏程序集的内容都视为隔离对象，范围过宽。

游戏清单 `ModManifest` 没有「角色模组」分类字段，只有 `id`、`name`、`author`、`description`、`version`、`dependencies` 等。不能靠名称或描述关键词可靠分类。

游戏提供两个可用事实：

1. `ModelDb.AllCharacters` 会包含模组注册的角色。BaseLib 通过 `CustomContentDictionary.CustomCharacters` 追加；RitsuLib 通过 `AllCharactersPatch` 追加。
2. 每个角色或内容的 `Type.Assembly` 可以映射到已加载的 `Mod`；RitsuLib 的 `ModContentRegistry.TryGetOwnerModId` 可以提供精确归属。

## 决策

自动识别角色模组，并把「角色模组内容」作为唯一隔离对象。

1. 在模组全部加载后，读取 `ModelDb.AllCharacters`。
2. 对每个非游戏程序集的角色类型，按程序集映射到模组；该模组标记为「已注册角色」。
3. 补充扫描模组程序集中的具体 `CharacterModel` 子类；未注册但存在的，标记为「检测到角色类（未注册）」，默认按角色模组处理，设置页允许关闭。
4. 没有注册角色、也没有具体角色类的模组，标记为「非角色模组」。
5. 归属无法解析的模组标记为「未知」。
6. 分类结果按模组 ID 缓存。自动模式使用自动结果；手动选择模式见 ADR-008，不读取自动结果。
7. 未知项默认不隔离，日志警告，设置页允许切换到手动选择模式指定。
8. 原版局只过滤「有效分类为角色模组」的模组所拥有的内容。非角色模组内容放行。
9. 角色集合过滤同样只移除角色模组的角色；非角色模组没有角色，通常不受影响。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 所有非游戏内容都隔离 | 范围过宽，误伤纯卡牌、纯遗物模组 |
| 按清单名称/描述关键词分类 | 不可靠，作者可任意填写 |
| 只扫描 `CharacterModel` 类型 | 未注册的类型可能误判；仍需注册角色作为主证据 |
| 只用 `ModelDb.AllCharacters` | 未注册或注册失败的角色模组无法识别；需要手动选择模式 |
| 硬编码角色模组名单 | 每装一个新模组都要改代码，不可维护 |
| 只按 RitsuLib 注册表 | 不覆盖 BaseLib 和直接注册的模组 |

## 后果

**获益**

- 标准角色模组可以自动识别；纯卡牌、纯遗物模组在原版局继续正常出现。
- 识别结果可解释：设置页显示自动依据，用户可以纠正。
- 手动选择模式可兜底共享程序集、动态注册、未注册角色等边界。
- 仍然不需要卸载模组，也不修改已有存档。

**代价**

- `ModelDb.AllCharacters` 的读取时机必须晚于所有模组注册。
- 角色模组与纯内容模组共用程序集时，归属可能不唯一；需要手动选择模式。
- 未注册角色类的扫描可能产生推测项；用户可以关闭。
- 未知项默认不隔离，可能漏掉异常角色模组；日志和设置页必须醒目提示。
- 需要额外的设置页列表、持久化键和诊断信息。

**下游规则**

1. 内容归属只回答「属于哪个模组」，不回答「是否隔离」。
2. 隔离判定必须同时读取「内容归属」与「角色模组分类」。
3. 非角色模组内容不得被自动隔离。
4. 自动识别结果不得硬编码模组 ID、角色名或卡牌名单。
5. 识别失败不得阻断游戏；默认不隔离该未知模组，并记录日志。
6. 手动选择模式的勾选列表必须持久化，至少影响下一局。
7. 识别必须在所有模组加载完成后执行；角色选择界面不得触发过滤。

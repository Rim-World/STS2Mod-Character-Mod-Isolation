# 001 隔离行为规范 v0.5

- 版本：0.5
- 状态：已废止；被 v0.6 取代
- 建立：2026-11-17 20:30
- 取代：`001-隔离行为规范-v0.4.md`。v0.5 放弃 0.107.1，新增仅检测已启用模组与自动模式过滤清单。
- 适用：Slay the Spire 2 0.111.0、0.113.1；单机标准局优先。

## 一、范围与术语

- **原版角色**：类型定义在游戏程序集 `sts2.dll` 中的可玩角色。
- **模组角色**：类型定义在第三方模组程序集中的角色。
- **角色模组**：至少注册了一个可玩角色的已启用模组；或由用户在设置中强制标记为角色模组的已启用模组。
- **非角色模组**：没有可玩角色，且没有被用户强制标记为角色模组的已启用模组。
- **角色模组内容**：归属为角色模组的卡牌、遗物、药水、事件、遭遇、先古、章节、角色。
- **未知归属**：内容类型或角色类型无法映射到已加载模组。
- **隔离**：在内容生成查询中排除角色模组内容，但不卸载模组、不修改已有存档、不排除非角色模组内容。
- **原版局**：本局所有玩家角色均为原版角色。

## 二、总则

- SP-001 模组必须在游戏启动时正常加载，不得修改任何第三方模组的启用状态。
- SP-002 隔离只影响本局新生成内容；不得删除、替换或改写已有存档中的内容。
- SP-003 隔离不得写入游戏安装目录、存档目录或第三方模组目录。
- SP-004 隔离对象仅限角色模组内容；非角色模组内容不得被自动隔离。

## 三、触发条件

- SP-005 仅当本局所有玩家角色均为原版角色时，隔离可以启用。
- SP-006 本局任一玩家角色为模组角色时，隔离不得启用。
- SP-007 不在局内时，隔离不得启用。
- SP-008 v1 在多人会话中不得启用隔离；日志必须写明跳过原因。
- SP-009 总开关关闭时，隔离不得启用。
- SP-010 隔离判定必须只读本局角色、已启用模组集合与设置；不得读取选人界面当前焦点或 UI 文本。

> 注记（非规范性）：角色按钮的解锁判定也读 `UnlockState.Characters`。过滤器只在局内启用；局外返回原集合，角色模组角色不会被锁。

## 四、角色与跨角色效果

- SP-011 原版局的 `UnlockState.Characters` 结果不得包含角色模组角色。
- SP-012 原版局的 `UnlockState.CharacterCardPools` 结果不得包含角色模组角色的卡池。
- SP-013 模组角色局的 `UnlockState.Characters` 与 `CharacterCardPools` 不得被本模组过滤。
- SP-014 原版局的 `Kaleidoscope.IsAllowedAtNeow` 必须按过滤后的角色卡池数与过滤后的角色数比较，不得因角色模组角色存在而恒为 false。
- SP-015 原版局中，任何读取全部角色卡池的效果必须只看到未被隔离的角色卡池。此类效果包括但不限于「飞溅」「恋人」「万花筒」「ocarina」「BottledSong」。
- SP-016 原版局中，跨角色效果返回的候选牌不得包含角色模组卡；非角色模组卡按原行为处理。

## 五、卡牌

- SP-017 原版局中，`CardPoolModel.GetUnlockedCards` 不得返回角色模组卡。
- SP-018 原版局中，角色模组卡池的 `GetUnlockedCards` 必须返回空集合，即使该池包含原版卡。
- SP-019 原版局中，原版卡池中混入的角色模组卡必须被移除；非角色模组卡不得被自动移除。
- SP-020 原版局中，「飞溅」的候选攻击牌不得包含角色模组卡；原版与非角色模组卡按原行为处理。
- SP-021 原版局中，卡牌奖励、商店、事件奖励、变形、发现、战斗内生成、药水生成的候选不得包含角色模组卡；非角色模组卡按原行为处理。

## 六、遗物与药水

- SP-022 原版局中，`RelicPoolModel.GetUnlockedRelics` 不得返回角色模组遗物。
- SP-023 原版局中，角色模组遗物池的 `GetUnlockedRelics` 必须返回空集合。
- SP-024 原版局中，`PotionPoolModel.GetUnlockedPotions` 不得返回角色模组药水。
- SP-025 原版局中，角色模组药水池的 `GetUnlockedPotions` 必须返回空集合。
- SP-026 原版局中，遗物抓袋、遗物奖励、商店遗物、事件遗物、药水掉落、事件药水不得包含角色模组遗物或角色模组药水；非角色模组遗物与药水按原行为处理。

## 七、事件、遭遇、先古与章节

- SP-027 原版局中，`ActModel.AllEncounters` 及其派生列表不得包含角色模组遭遇。
- SP-028 原版局中，`ModelDb.AllSharedEvents` 与具体章节的 `AllEvents` 不得包含角色模组事件。
- SP-029 原版局中，`ActModel.PullNextEvent` 不得返回角色模组事件；若房间列表残留角色模组事件，必须在返回前移除。
- SP-030 原版局中，`ModelDb.AllSharedAncients`、具体章节的 `AllAncients` 与 `GetUnlockedAncients` 不得包含角色模组先古。
- SP-031 原版局中，`ActModel.GenerateRooms` 使用的先古候选不得包含角色模组先古。
- SP-032 原版局中，`ModelDb.ActsByIndex` 不得包含角色模组章节。
- SP-033 章节列表在 `RunManager.State` 建立前选择时，必须使用选人界面已选角色的待定上下文；解析失败时不得隔离章节。

## 八、内容归属

- SP-034 内容归属必须按模型类型的程序集映射到已加载模组。
- SP-035 若 RitsuLib 可用，可以优先使用 `ModContentRegistry.TryGetOwnerModId` 的精确归属。
- SP-036 无法映射的非游戏程序集类型必须按未知归属处理，不得自动隔离，并记录一次警告。
- SP-037 框架程序集的辅助类型不得被视为角色模组内容；框架程序集里的具体模型类型按非游戏程序集处理。
- SP-038 归属结果必须按类型缓存；不得在每次内容查询时重新遍历全部程序集。
- SP-039 内容归属只回答「属于哪个模组」；是否隔离必须再由角色模组分类与运行上下文决定。

## 九、失败与安全

- SP-040 过滤方法不得向游戏抛出未处理异常。
- SP-041 过滤方法抛出异常时必须返回未过滤结果，并记录限流日志。
- SP-042 核心补丁（角色集合、卡池、遗物池、药水池）任一失败时，必须整体关闭隔离。
- SP-043 非核心分类补丁失败时，可以只关闭该分类；日志必须写明补丁 ID。
- SP-044 隔离判定必须确定：相同本局角色、相同模组集合、相同隔离来源与相同手动勾选集合必须得到相同结果。
- SP-045 隔离不得改变本局随机数种子或玩家输入；过滤只改变候选列表。
- SP-046 过滤后的候选为空时，不得抛出异常；必须记录日志，并按该调用点的原版空列表行为处理。

## 十、设置

- SP-047 总开关默认开启。
- SP-048 卡牌、遗物、药水、事件/遭遇、先古/章节分类开关默认开启。
- SP-049 v1 不得提供多人开启开关；多人会话必须跳过隔离。
- SP-050 设置必须持久化；读取失败时必须回到默认值并记录日志。
- SP-051 设置变更只影响下一局；本局判定不得中途改变。
- SP-052 设置键名发布后不得改名；结构变更必须提供迁移或整体重置规则。
- SP-053 设置页必须提供互斥的「自动识别」与「手动选择」两种隔离来源。自动模式只显示已启用且被识别为角色模组的模组；手动模式列出已启用模组并允许勾选。
- SP-054 手动选择模式必须跳过自动识别；不得读取 `ModelDb.AllCharacters`、不得扫描具体 `CharacterModel` 子类、不得构建自动分类。

## 十一、诊断

- SP-055 日志必须包含：是否隔离、原因、已启用模组数、当前隔离来源、自动模式下的角色模组、手动模式下的勾选数量、未知归属、每次过滤移除数量。
- SP-056 日志不得包含玩家账号、Steam ID、存档路径中的用户名。
- SP-057 详细日志默认关闭；开启后不得改变过滤结果。

## 十二、兼容

- SP-058 单程序集必须能在 0.111.0、0.113.1 加载。
- SP-059 运行期不得引用只在 0.113 存在的类型或枚举值。
- SP-060 模组加载器字段必须通过反射读取，不得依赖单一版本字段形状。
- SP-061 章节生成必须按版本补丁 `GenerateRooms` 存在的重载；代码不得直接调用该方法。
- SP-062 清单 `min_game_version` 必须写 `0.111.0`。
- SP-063 补丁目标找不到时必须记录并跳过，不得阻断其他补丁。

## 十三、角色模组识别

- SP-064 角色模组识别必须在所有模组加载完成后执行；不得在模组注册完成前缓存结果。
- SP-065 自动识别必须读取 `ModelDb.AllCharacters`；类型不来自游戏程序集的角色必须按其程序集映射到模组，并把该模组标记为角色模组。
- SP-066 可以补充扫描模组程序集中的具体 `CharacterModel` 子类；未注册的角色类只能标记为「可能角色」，默认按角色模组处理，设置页允许关闭；可能角色不得覆盖已注册角色的结论。
- SP-067 自动模式下的角色模组分类必须按模组 ID 缓存；手动模式不得读取或使用自动分类。
- SP-068 无法识别或无法归属的模组默认不得自动隔离；设置页必须允许用户手动标记为角色模组或非角色模组。
- SP-069 非角色模组内容不得被本模组自动过滤；在关闭隔离、无角色模组或手动标记为非角色时，必须返回原结果。
- SP-070 角色模组识别失败不得阻断游戏；受影响模组按未知处理，不自动隔离，并记录日志。
- SP-071 自动模式设置页必须显示每个已启用且被识别为角色模组的模组名称、ID、分类、依据与过滤状态；没有结果时必须显示空状态。
- SP-072 角色模组识别不得硬编码模组 ID、角色名或卡牌名单。

## 十三之二、手动选择模式

- SP-073 手动模式的有效隔离集合必须严格等于用户勾选的已启用模组集合；未勾选或禁用的模组不得参与过滤。
- SP-074 手动模式未勾选任何模组时，不得隔离任何内容。
- SP-075 隔离来源模式与手动勾选列表必须持久化；变更只影响下一局。
- SP-076 手动模式仍必须运行内容归属映射，以确定内容属于哪个模组；归属失败的内容不得自动过滤。
- SP-077 自动模式按 SP-064 至 SP-072 执行；手动模式不得读取或使用这些自动识别结果。
- SP-078 自动识别必须只枚举已启用模组；禁用模组不得进入 `ModelDb.AllCharacters` 扫描、程序集扫描、自动分类缓存或日志。禁用模组的既有归属记录不得用于过滤。
- SP-079 自动模式设置页与手动选择列表不得显示禁用模组；手动勾选集合中的禁用 ID 不得参与有效隔离集合。
- SP-080 自动模式过滤状态必须区分「本局已触发过滤」「已检测但本局未触发」与「进入原版角色局后生效」；状态不得由设置页另造角色判定。

## 十四、非规范性说明

以下内容不进入验证：

- 角色模组对原版代码的直接 Harmony 补丁不在隔离范围。
- 图鉴、卡牌库、遗物图鉴不隐藏模组条目。
- 旧存档中的模组内容保留。
- 多人配置同步不在 v1 范围。
- 角色模组与纯内容模组共用程序集时的归属歧义，需要手动选择模式。
- 未注册且未被扫描到的角色模组，可能按未知处理，需要用户手动标记。

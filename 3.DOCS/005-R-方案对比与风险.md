# 005-R 方案对比与风险

- 建立时间：2026-11-17 02:16
- 目的：在多个可行方案中选择一个，并列出风险与缓解。

## 一、方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A 现状：关模组并重启 | 在模组设置关闭角色模组 | 行为最干净；无兼容风险 | 每次切换要重启；容易忘记；不能同局混用 | 保留为兜底 |
| B 多游戏目录/多配置 | 复制游戏或维护两套 mods | 隔离彻底 | 占空间；更新麻烦；存档路径复杂 | 不推荐 |
| C 模组加载器按局启用 | 修改加载器，按局加载 DLL | 理论最彻底 | DLL 不能卸载；内容池缓存；需改游戏/加载器 | 不可行 |
| D 运行期内容过滤 | 按本局角色集合过滤池与章节内容 | 不需重启；模组保持启用；可配置 | 不能隔离代码补丁；有补丁顺序与边界 | **推荐** |
| E 按当前角色模组白名单 | 只允许当前角色所属模组的内容 | 更严格 | 跨模组内容会断；依赖关系复杂；维护成本高 | v1 不做 |

## 二、推荐方案

方案 D：运行期内容过滤。先识别角色模组，再做三层布防。

隔离对象只限角色模组内容。角色模组由自动识别或手动选择模式确定；纯卡牌、纯遗物等非角色模组内容放行。

1. 角色集合：`UnlockState.Characters`。
2. 池查询：`GetUnlockedCards` / `GetUnlockedRelics` / `GetUnlockedPotions`。
3. 章节内容：`ActModel` 的遭遇/事件/先古/章节列表，加消费端兜底。

判定条件：本局所有玩家角色为原版、单机、总开关开。模组角色局、多人、读取失败均不过滤。

## 三、风险

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 角色模组直接补丁原版代码 | 中 | 隔离不完整 | 文档写明边界；不承诺 |
| 角色模组绕过池注入奖励 | 中 | 少量模组卡出现在原版局 | 可选严格模式在奖励/战斗生成出口再过滤 |
| 角色模组识别失败或误判 | 中 | 该隔离的没隔离，或不改隔离的被隔离 | 设置页显示自动依据；可切换手动模式只勾选需要隔离的模组；未知默认不隔离 |
| 补丁顺序落后于 BaseLib/RitsuLib | 中 | 过滤后又被追加内容 | HarmonyAfter + Priority.Last；事件消费端兜底；运行日志验证 |
| 多人配置不一致 | 中 | 状态发散 | 默认多人关闭；显式开启需全员同配置 |
| 旧存档含模组内容 | 高 | 旧局仍有模组内容 | 只过滤新生成；文档写明 |
| 旧版成员缺失 | 低 | 加载失败 | 只用三版一致成员；反射差异；旧版实测 |
| 过滤后候选为空 | 低 | 个别效果无牌可选 | 记录错误；不抛异常；规范定义空结果行为 |
| 图鉴仍显示模组内容 | 高 | 界面不一致 | v1 不隐藏；如需隐藏另开需求 |
| 性能开销 | 低 | 发牌轻微变慢 | 归属缓存；只做列表过滤 |
| RitsuLib 依赖增加安装门槛 | 中 | 玩家需多装一个框架 | 文档写明；或改自写 JSON 配置 |

## 四、风险优先级

1. **补丁顺序**：最可能在真实环境出现，必须先做运行日志验证。
2. **代码补丁边界**：用户预期管理最重要；必须在 README 与工坊说明写明。
3. **多人默认关闭**：避免最严重的状态发散。
4. **旧存档**：不清理是正确行为，但需要明确告知。
5. **严格模式**：默认关闭，避免候选变少引发新问题。

## 五、为什么不用「按角色模组白名单」

更严格的方案是：玩模组角色 A 时，只启用模组 A 的内容，隐藏模组 B 的角色卡/遗物/事件。它看起来更干净，但有两个问题：

1. 角色模组可能依赖另一个内容模组的卡牌/遗物；按模组切断会破坏内容。
2. 需要维护「角色 → 模组 → 依赖」的映射，跨模组兼容成本高。

用户的核心诉求是「原版角色不受角色模组影响」，不是「模组之间互相隔离」。因此 v1 只做原版/角色模组二分：原版局隐藏角色模组内容，纯内容模组保留；模组角色局不做模组间隔离。

## 六、结论

方案 D 可行性与收益最高。先做单机、原版/角色模组二分、默认开启；多人、严格模式、图鉴隐藏作为后续可选。

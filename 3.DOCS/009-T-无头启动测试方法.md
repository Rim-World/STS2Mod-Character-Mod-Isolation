# 009-T 无头启动测试方法

- 建立时间：2026-11-17 05:25
- 适用：本机、Windows、Slay the Spire 2 0.113.1、当前项目 0.1.0
- 来源：`C:\Users\13167\Desktop\Mod\STS2Mod-优化棱彩宝石\3.DOCS\015-T-无头启动测试方法.md`
- 用途：验证模组加载链，不验证游戏内战斗与内容生成

## 一、能证明什么

无头启动会正常走游戏加载流程，但没有窗口和渲染。

可以证明：

- 游戏发现模组清单与程序集。
- 游戏调用了本模组的 `[ModInitializer]`。
- RitsuLib 设置页注册成功。
- 补丁注册与安装数量可读。
- 本地化条目数与回退数可读。
- 自动识别、手动模式开关在加载阶段的行为。
- 程序集版本与部署位置一致。

不能证明：

- 设置页的排版、字号、点击与翻页。
- 对局内发牌、商店、事件、遭遇、先古、章节的实际结果。
- 角色模组角色局的实际游玩。
- 存档读写的完整路径。

## 二、前置条件

1. Steam 客户端已启动并登录。
2. 游戏版本与目标版本一致；查看 `release_info.json`。
3. 本模组已经构建并部署到游戏目录。
4. 游戏进程未在运行；否则 DLL 被占用，构建部署可能失败。
5. 测试期间不要让第二个启动器同时启动游戏。

本机路径：

```text
游戏目录：C:\Game\Steam\steamapps\common\Slay the Spire 2
游戏日志：C:\Users\13167\AppData\Roaming\SlayTheSpire2\logs\godot.log
模组目录：C:\Game\Steam\steamapps\common\Slay the Spire 2\mods\CharacterModIsolation
```

## 三、构建与部署

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File 9.SRC/tools/check-ritsu-version.ps1
```

```bash
cd "C:/Users/13167/Desktop/Mod/STS2Mod-角色mod屏蔽"
dotnet build 9.SRC/CharacterModIsolation.csproj -c Release
```

`csproj` 的 `CopyModToGame` 目标会把 DLL 与清单复制到游戏模组目录。若游戏正在运行，复制会警告但不影响编译；关闭游戏后重新构建。

确认部署：

```bash
ls -l "C:/Game/Steam/steamapps/common/Slay the Spire 2/mods/CharacterModIsolation"
```

## 四、启动

在 Git Bash 中执行：

```bash
cd "C:/Game/Steam/steamapps/common/Slay the Spire 2"
SteamAppId=2868840 ./SlayTheSpire2.exe --headless
```

三段的作用：

| 参数 | 作用 |
|---|---|
| `SteamAppId=2868840` | 给 Steamworks 提供 AppID；缺失会初始化失败 |
| `--headless` | 不创建窗口，加载流程照常 |
| `./SlayTheSpire2.exe` | 直接启动游戏本体 |

`--headless` 不会自动退出。测试脚本应把它放到后台，等待日志标记，然后结束进程。

## 五、等待与判据

本模组在主菜单事件中输出：

```text
[CharacterModIsolation] [init] main menu ready
```

等待命令：

```bash
LOG="/c/Users/13167/AppData/Roaming/SlayTheSpire2/logs/godot.log"
for i in $(seq 1 90); do
  sleep 1
  if grep -q "main menu ready" "$LOG" 2>/dev/null; then
    echo "READY at ${i}s"
    break
  fi
done
```

本机 0.113.1 实测约 47 至 48 秒。首次启动或资产较多时允许更长等待。

加载通过的日志应包含：

```text
[CharacterModIsolation] [init] CharacterModIsolation 0.1.0.0
[CharacterModIsolation] [patches] installed=51 failed=0
[CharacterModIsolation] [settings] page registered
[CharacterModIsolation] [init] main menu ready
```

自动模式还应包含：

```text
[CharacterModIsolation] [auto] built.
```

手动模式不应包含：

```text
[CharacterModIsolation] [auto]
```

## 六、保存日志与结束

先复制日志，再结束进程。游戏每次启动会轮转日志，复制太晚会丢证据。

```bash
cp "$LOG" \
  "C:/Users/13167/Desktop/Mod/STS2Mod-角色mod屏蔽/8.TEST/0.1.0/本次测试.log"
```

结束进程：

```bash
cmd.exe /c "taskkill /F /IM SlayTheSpire2.exe"
```

不要使用 `taskkill //F //IM`。本机 Git Bash 会把双斜杠当成路径参数，`taskkill` 报 `Invalid argument/option`。

结束后确认：

```bash
powershell -NoProfile -Command "Get-Process SlayTheSpire2 -ErrorAction SilentlyContinue"
```

没有输出即已结束。

## 七、日志校验

项目内脚本：

```bash

```

`auto` 检查自动识别与 51 个补丁；`manual` 检查无 `[auto]` 行。脚本只检查文本事实，不替代游戏内验收。

## 八、常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志很短，出现 `No appID found` | 缺少 `SteamAppId` | 加上环境变量重跑 |
| 卡在 Steamworks 初始化 | Steam 未运行或未登录 | 登录 Steam 后重跑 |
| 找不到模组日志 | 清单或 DLL 未部署，或 mod ID 不一致 | 检查 `mods/CharacterModIsolation` |
| 日志里是旧版本内容 | 读到了旧日志 | 先看文件时间戳，或按本次启动时间复制 |
| 构建提示部署失败 | 游戏进程占用 DLL | 结束进程后重新构建 |
| `taskkill` 参数错误 | Git Bash 把 `/F` 改写 | 使用 `cmd.exe /c "taskkill /F /IM ..."` |
| 无头进程一直不退出 | `--headless` 设计如此 | 先复制日志，再结束进程 |

## 九、测试边界

无头测试通过只代表加载链通过。游戏内卡牌、遗物、药水、事件、遭遇、先古与章节的过滤，必须按 [游戏内验收清单](../8.TEST/0.1.0/游戏内验收清单.md) 实际游玩验证。

## 十、AutoSlayer 与场景模式

游戏内置 AutoSlayer。发行版的 `NGame.IsReleaseGame()` 返回 `true`，需要临时 Harmony 后置补丁把它改成 `false` 才会进入测试分支。

### 10.1 内置 AutoSlayer

```bash
cd "/c/Game/Steam/steamapps/common/Slay the Spire 2"
SteamAppId=2868840 timeout 600 ./SlayTheSpire2.exe --headless --autoslay --seed=1 --mode=standard --log-file="本次日志.log"
```

启动参数：

- `--autoslay`：启动完整自动跑局。
- `--seed`：固定种子。
- `--mode`：`standard`、`blitz`、`dread`。
- `--log-file`：AutoSlayer 专用日志。

AutoSlayer 自己选角色、走路、战斗、选奖励，完成后退出。最长运行时间由 `AutoSlayConfig.runTimeout` 限制为 25 分钟。

### 10.2 场景模式

`--scenario` 是 AutoSlayer 的确定性入口：

```bash
SteamAppId=2868840 ./SlayTheSpire2.exe --headless \
  --scenario="本次场景.scenario" --seed=1 --fast-mode=fast \
  --log-file="本次日志.log"
```

场景脚本支持：

- 游戏控制台命令，例如 `event COLORFUL_PHILOSOPHERS`。
- `wait <秒>`。
- `wait combat-started`、`wait turn-started`。
- `endturn`。

场景模式固定用铁甲创建新单人局，设置 `shouldSave:false`，然后用控制台命令改变房间或战斗。

### 10.3 本模组的场景限制

ScenarioRunner 直接创建新局，不经过主菜单。本模组目前把补丁安装挂在 `MainMenuReadyEvent`，所以场景模式里补丁默认不安装。

测试时用临时探针 `8.TEST/0.1.0/AutoSlayProbe` 反射调用：

```text
CharacterModIsolation.PatchRegistry.InstallAll()
```

这样可以在场景模式里得到 51 个补丁，验证过滤器。探针只用于测试，不进入发布物。

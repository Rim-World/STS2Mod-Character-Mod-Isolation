# 002-E 游戏内容注册与生成链路取证

- 建立时间：2026-11-17 02:16
- 证据基线：`STS2-Reference/4.STS2-113.1Reference/decompiled`，游戏 `v0.113.1`、commit `d09d48e5`。
- 说明：行号以该基线为准；三版差异见 [003-E](003-E-三版本API对照.md)。

## 一、模组加载

| 事实 | 证据 | 含义 |
|---|---|---|
| 游戏从可执行文件旁 `mods/` 与 Steam 创意工坊读取清单 | `MegaCrit.Sts2.Core.Modding/ModManager.cs:70-125` | 角色模组与普通模组走同一加载器 |
| 每个模组只加载 `<mod_id>.dll` | `ModManager.cs:797-815` | DLL 名称必须等于清单 ID |
| 有 `[ModInitializer]` 时调用初始化方法，否则 `Harmony.PatchAll` | `ModManager.cs:840-865` | 角色模组通常在初始化时注册内容/补丁 |
| 模组状态与程序集记录在 `Mod` | `Mod.cs:30-48` | 可用于反查归属 |
| DLL 加载后不卸载 | `Mod.cs:11-30` 注释；`ModManager` 无卸载路径 | 无法按局禁用模组，只能过滤内容视图 |

## 二、内容注册

| 事实 | 证据 | 含义 |
|---|---|---|
| 模组通过 `ModHelper.AddModelToPool(poolType, modelType)` 把模型加入池 | `MegaCrit.Sts2.Core.Modding/ModHelper.cs:49-69` | 卡牌/遗物/药水的标准注入点 |
| 池首次访问时把模组类型拼接到原版列表并缓存 | `ModHelper.cs:78-93`；`CardPoolModel.cs:44-55` | 过滤应在查询出口，不应重建池 |
| 卡池、遗物池、药水模型都调用 `ConcatModelsFromMods` | `CardPoolModel.cs:51`；`RelicPoolModel.cs:29-36`；`PotionPoolModel.cs:31-38` | 三类内容同一机制 |
| `AddModelToPool` 只记录类型，不记录模组 ID | `ModHelper.cs:54-69` | 归属需要从类型所在程序集反推 |

## 三、角色与卡池

| 事实 | 证据 | 含义 |
|---|---|---|
| 角色模型声明 `CardPool`、`RelicPool`、`PotionPool`、`StartingDeck`、`StartingRelics` | `CharacterModel.cs:128-146` | 角色模组的自定义内容围绕这三个池 |
| `UnlockState.Characters` 从 `ModelDb.AllCharacters` 取角色，再按 epoch 移除未解锁 | `UnlockState.cs:57-84` | 单一角色集合出口 |
| `UnlockState.CharacterCardPools` 直接由 `Characters` 派生 | `UnlockState.cs:112-115` | 过滤角色集合即可影响所有跨角色效果 |
| `ModelDb.AllCharacters` 在 0.113.1 硬编码 6 个原版角色 | `ModelDb.cs:146-154` | 模组角色通过 Harmony 后置追加，不能按数量判断原版 |

## 四、「飞溅」链路

| 步骤 | 证据 |
|---|---|
| 取已解锁角色卡池 | `MegaCrit.Sts2.Core.Models.Cards/Splash.cs:25` |
| 多于一个池时移除自己角色的池 | `Splash.cs:26-29` |
| 每个池调用 `GetUnlockedCards`，只留攻击牌 | `Splash.cs:30-32` |
| `CardFactory.GetDistinctForCombat` 抽 3 张 | `Splash.cs:33` |
| 玩家选 1 张，免费入手 | `Splash.cs:40-58` |

结论：不需要重写 `Splash.OnPlay`。过滤 `UnlockState.Characters` 与 `GetUnlockedCards` 即可。

## 十、同向前作

| 项目 | 事实 | 证据 |
|---|---|---|
| SplashExclusion | 重写 `Splash.OnPlay`，按标签过滤候选；多人默认禁用 | `STS2Mod-优化棱彩宝石/3.DOCS/001-R-SplashExclusion机制调研.md` |

结论：过滤 Splash 候选与奖励候选已有实际作品验证；本项目的差异是把过滤条件从「卡牌分组」提升为「内容归属 + 本局角色集合」，覆盖全部内容类别。

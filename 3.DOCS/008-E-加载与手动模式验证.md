# 008-E 加载与手动模式验证

- 建立时间：2026-11-17 04:55
- 验证对象：CharacterModIsolation 0.1.0
- 验证方式：游戏 0.113.1，`--headless`，只到主菜单；未进入战斗或对局
- 结论：加载、补丁安装、设置页注册、手动模式跳过自动识别、MGRMod 自动识别均通过；游戏内内容过滤尚未验证

## 一、环境

| 项 | 值 |
|---|---|
| 游戏 | v0.113.1，commit `d09d48e5` |
| 启动方式 | `SteamAppId=2868840 SlayTheSpire2.exe --headless` |
| 模组 | `mods/CharacterModIsolation/`，DLL 0.1.0.0 |
| RitsuLib | 0.6.14，变体入口 `0.113.0` |
| 角色模组 | MGRMod 0.8.1（Steam Workshop 3784531815），测试时临时启用，测试后恢复禁用 |

## 二、结果

### 2.1 自动模式加载

日志：`8.TEST/0.1.0/2026-11-17-1131-主菜单加载与51补丁.log`

- 初始化方法被调用，版本 `0.1.0.0`。
- 补丁安装：`installed=51 failed=0`。
- 设置页注册成功。
- 文案：`entries=37, local=37, fallbackEntries=0`。
- 自动识别：`mods=38 character=0`。
- 没有本模组的 ERROR/Exception。

`character=0` 的直接原因是 MGRMod 在游戏设置中被禁用，启动日志出现 `Skipping loading mod MGRMod, it is set to disabled in settings`。这组日志只证明无角色模组时加载正常。

### 2.1b MGRMod 启用后的自动识别

日志：`8.TEST/0.1.0/2026-11-17-MGR启用-自动识别.log`

- 用户允许临时修改 `settings.save`；测试前备份，测试后恢复禁用状态。
- MGRMod 0.8.1 加载，Pak 与程序集均成功。
- 补丁安装：`installed=51 failed=0`。
- 自动识别：`mods=39 character=1`。
- 识别结果：`MGRMod kind=Character reason=已注册角色`。
- 文本加载：`entries=37, local=37, fallbackEntries=0`。
- 没有本模组的 ERROR/Exception。

这证明自动识别能从 `ModelDb.AllCharacters` 找到 MGR 的角色类型，并通过程序集归属映射到 `MGRMod`。

### 2.2 手动模式

日志：`8.TEST/0.1.0/2026-11-17-手动模式-51补丁.log`

- 设置文件临时设为 `Source=1`、`ManualModIds=[]`。
- 日志中没有 `[CharacterModIsolation] [auto]` 行。
- 补丁安装仍为 `installed=51 failed=0`。
- 设置页注册成功。
- 测试后设置文件已恢复为自动模式。

结论：手动模式确实跳过自动识别。

另一次测试在 MGRMod 启用、设置来源为手动、勾选集合为 `MGRMod` 的条件下启动：

- 日志：`8.TEST/0.1.0/2026-11-17-MGR启用-手动模式.log`
- 日志中没有 `[CharacterModIsolation] [auto]`。
- 补丁安装：`installed=51 failed=0`。
- 设置页注册成功。
- 测试后 `settings.save` 与模组设置均已恢复。

这证明手动模式不会因为角色模组已加载而偷偷运行自动识别。

## 三、未验证项

- 原版角色局卡牌、遗物、药水、事件、遭遇、先古、章节的实际过滤。
- 角色模组角色局是否保持正常。
- 读档、多人、0.107.1、0.111.0。

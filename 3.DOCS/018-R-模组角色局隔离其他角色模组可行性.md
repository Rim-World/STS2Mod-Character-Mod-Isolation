# 018-R 模组角色局隔离其他角色模组可行性

- 调研时间：2026-11-23 02:29
- 调研方式：只读。阅读当前源码、反编译游戏代码、已安装模组加载日志；未改代码，未启动游戏。
- 结论：**可行，属于中等改动，不需要重做过滤架构。**
- 关联文档：[001-R](001-R-角色模组隔离可行性调研.md)、[004-E](004-E-第三方角色模组实现方式取证.md)、[014-E](014-E-MGR角色局不隔离验证.md)、[017-E](017-E-飞溅候选验证.md)。
- 关联需求：RQ-006、RQ-007、RQ-019、RQ-020、RQ-022。
- 施工计划：[010-M](../2.PLANS/010-M-模组角色局保护当前模组.md)。
- 关联决策：[ADR-010](../4.ADR/010-保护当前角色模组并隔离其他模组.md)。

## 一、结论

现有实现把「原版角色局」和「模组角色局」当成二元状态。原版角色局隔离全部角色模组；模组角色局直接停用过滤，因此其他角色模组的内容也保留。

新需求不需要卸载、禁用或重启模组。只需要把运行上下文改成「保护当前角色所属模组，隔离其余角色模组」。

核心判定仍然是内容类型到模组 ID 的归属映射，不需要硬编码 `MGRMod`、`Watcher`、角色名或卡牌 ID。

## 二、需求边界

推荐的首版行为：

- 选人界面仍显示全部已启用角色模组。选人不受本功能影响。
- 单人标准局中，当前角色来自角色模组 A 时，A 的卡牌、遗物、药水、事件、遭遇、先古、章节保留。
- 同一局中，其他角色模组的内容从运行期内容池移除。
- 当前角色是原版角色时，移除全部角色模组内容。该行为与现有版本一致。
- 当前角色来自角色模组，且没有其他角色模组时，不做过滤。
- 手动模式沿用原有语义：只处理勾选的角色模组；当前角色所属模组始终保留。

不纳入首版的范围：

- 多人模式。当前代码在 `Players.Count != 1` 时停用过滤。
- 随机角色。选幕发生在随机角色解析之前，待选幕次无法可靠确定当前角色归属。
- 图鉴、控制台、全局统计中的模组内容。它们不属于本局内容池。
- 已保存的原版角色存档中的模组卡牌。隔离只影响之后新生成的内容。
- 角色模组直接修改原版代码的 Harmony 补丁。内容过滤不会撤销这些补丁。

## 三、现状

### 3.1 当前运行上下文按二元状态处理

`9.SRC/src/Runtime/RunContext.cs` 的待定上下文读取选人界面角色：

- `SetPendingFromLobby` 在发现模组角色时直接返回 `mod-character`，不进入过滤状态。见 `9.SRC/src/Runtime/RunContext.cs:193-196`。
- `Evaluate` 在运行状态中发现模组角色时调用 `SetInactive(..., "mod-character")`。见 `9.SRC/src/Runtime/RunContext.cs:285-288`。

因此当前模组角色局不会触发卡池、角色列表、事件、遭遇、先古和章节过滤。

### 3.2 过滤判定没有保护集

`9.SRC/src/Runtime/FilterPolicy.cs` 的所有判定都使用 `CharacterModRegistry.GetIsolatedOwner(type)`。当前没有「当前角色所属模组不得移除」这一层。

如果只从 `RunContext.EffectiveModIds` 中减去当前模组，`GetIsolatedOwner` 仍会返回当前模组 ID，当前模组的卡牌和卡池仍会被移除。因此必须在过滤判定层增加保护集。

### 3.3 内容归属映射已经存在

`9.SRC/src/Runtime/ContentOwnership.cs:81` 的 `GetOwnerModId` 已通过程序集映射和游戏 `AssemblyInfo` 归属信息返回模组 ID。

0.111.1 的实测日志识别到：

```text
[auto] character=MGRMod kind=Character
[auto] character=Watcher kind=Character
```

证据：`8.TEST/0.2.0/20261118-0142-1111-full-splash.stdout` 的 `[auto] character=` 行。

因此当前角色所属模组可以从角色模型类型取得，不需要读取角色名称。

### 3.4 现有过滤链可以复用

- 角色集合：`9.SRC/src/Patches/CharacterPatches.cs:8-20` 过滤 `UnlockState.Characters`。
- 卡牌：`9.SRC/src/Patches/PoolPatches.cs:16-37` 过滤 `CardPoolModel.AllCards` 源数组；`:45-71` 过滤 `GetUnlockedCards` 结果。
- 遗物与药水：同一文件按池和内容类型过滤。
- 事件、遭遇、先古、章节：`9.SRC/src/Patches/ActPatches.cs` 的多个后置与前缀补丁。
- 「飞溅」：`Splash.OnPlay` 读取 `UnlockState.CharacterCardPools`，再调用 `GetUnlockedCards` 和 `GetDistinctForCombat`。见 `2.STS2-111Reference/decompiled/MegaCrit.Sts2.Core.Models.Cards/Splash.cs:25-33`。

因此新需求不需要新增「飞溅专用补丁」。只要角色集合、卡池和内容归属判定正确，飞溅会自动看到正确内容。

## 四、目标行为

定义：

- `A`：当前角色所属模组 ID。原版角色时为空。
- `E`：本局有效的角色模组集合。自动模式为自动识别出的角色模组；手动模式为已勾选且启用的模组。
- `P`：保护集，等于 `{A}`；原版角色时为空。
- `I`：隔离集，等于 `E - P`。

行为：

| 当前角色 | 保护集 `P` | 隔离集 `I` |
|---|---|---|
| 原版角色 | 空 | 全部已启用角色模组 |
| MGR 角色 | `MGRMod` | `Watcher` 及其他角色模组 |
| Watcher 角色 | `Watcher` | `MGRMod` 及其他角色模组 |
| 仅有一个角色模组，且本局使用它 | 该模组 | 空 |
| 当前模组无法确定 | 空，记录警告 | 按失败策略处理，见第六节 |

`A` 必须从 `ContentOwnership.GetOwnerModId(player.Character.GetType())` 取得。不得从角色显示名、角色 ID 文本或模组白名单推断。

## 五、实现方案

### 5.1 扩展 `RunContext`

增加：

```text
ProtectedModIds   当前角色所属模组集合
IsolatedModIds    实际隔离集合
PolicyVersion     运行上下文与过滤策略版本
```

修改：

- `SetPendingFromLobby` 不再在 `mod-character` 时直接停用。
- `Evaluate` 不再在 `mod-character` 时直接停用。
- 单人读取 `player.Character` 的模组归属，建立保护集。
- 自动模式从 `CharacterModRegistry.AutoCharacterModIds()` 建立有效集合。
- 手动模式从 `ModSettings.ManualModIds` 建立有效集合。
- 隔离集为空时停用过滤，并记录 `no-other-character-mods`。
- 原版角色且存在角色模组时，记录 `vanilla-run`。
- 模组角色且存在其他模组时，记录 `mod-character-other`，并在日志中写出保护模组 ID。

待定上下文也要保存保护集与隔离集，因为章节列表在 `RunManager.State` 建立前就会生成。

### 5.2 统一过滤判定

在 `FilterPolicy` 增加：

```text
owner = CharacterModRegistry.GetIsolatedOwner(type)
remove = owner != null
      && RunContext.IsActiveForCategory
      && !RunContext.IsProtectedOwner(owner)
```

`ShouldRemoveCharacter`、`ShouldRemoveCard`、`ShouldRemoveRelic`、`ShouldRemovePotion`、`ShouldRemoveEvent`、`ShouldRemoveEncounter`、`ShouldRemoveMonster`、`ShouldRemoveAncient`、`ShouldRemoveAct`、`ShouldRemoveActForRun` 以及四个 `ShouldEmpty*Pool` 都使用这一判定。

必须特别检查：

- `ShouldRemoveCharacter`：当前角色不能被从 `UnlockState.Characters` 移除。
- `ShouldEmptyCardPool`：当前角色的卡池不能被清空。
- `ShouldRemoveCard`：当前模组的卡牌必须保留。
- `ShouldRemoveRelic`、`ShouldRemovePotion`：当前模组的遗物和药水必须保留。
- `ShouldRemoveEvent`、`ShouldRemoveEncounter`、`ShouldRemoveAncient`、`ShouldRemoveAct`：当前模组的内容必须保留。

仅在 `RunContext` 里减去当前模组不够，因为 `GetIsolatedOwner` 仍会独立返回当前模组 ID。

### 5.3 章节待定上下文

`9.SRC/src/Patches/ActPatches.cs:307-311` 在 `BeginRunLocally` 前建立待定上下文；`ActModel.GetRandomList` 后置会清理待定上下文。

新逻辑必须在待定上下文中同时保存保护集。否则选幕阶段会把当前模组的章节或事件移除。

当前模组角色局如果存在其他角色模组，待定状态必须为启用；如果只有当前模组，则可以为停用，因为无需隔离其他模组。

### 5.4 缓存失效

`9.SRC/src/Patches/PoolPatches.cs:8-37` 的 `SourceCache` 只有 `Source` 与 `Filtered`。它没有记录过滤策略版本。

同一进程内先跑原版角色局，再跑 MGR 角色局时，源数组引用可能相同，过滤数组不会重建。结果是原版局生成的过滤结果继续删除 MGR 卡牌，或模组局结果污染下一局。

必须给缓存增加策略版本：

```text
Source          源数组
PolicyVersion   过滤策略版本
Filtered        过滤结果
```

策略版本至少应在以下情况变化：

- 当前运行状态改变。
- 保护集或隔离集改变。
- 自动/手动来源改变。
- 过滤分类开关改变。

还要检查以下缓存：

- `CardPoolModel.AllCardIds`：可能缓存过滤后的 ID 集合。
- `ModelDb.AllCards`：`ModelDb.cs:114` 在 `Preload` 中一次构建，见 `ModelDb.cs:484`。它可能早于本局过滤，不应作为本功能的运行期唯一出口。
- `ModelDb.AllCharacters`：现有代码只在 Orobas 等少数作用域过滤，不能保证所有读取方都看到隔离结果。

至少要在运行切换和设置切换时让本模组的过滤缓存失效。

### 5.5 设置页与日志

`9.SRC/src/ModSettings.cs:332-343` 的 `AutoStatus` 目前只检查 `EffectiveModIds`。当前角色模组不在有效集合后，会显示为「本局未触发」。

需要增加：

- `ProtectedModIds` 状态：当前角色模组，保留。
- `IsolatedModIds` 状态：本局已隔离。
- 原版角色状态：本局将隔离全部角色模组。
- 空状态：没有其他角色模组可隔离。

相关文案：

- `9.SRC/localization/eng.json:4`、`zhs.json`、`zht.json` 的页面说明。
- `:43-45` 的三态状态文案。
- `9.SRC/src/ModSettings.cs:213` 的页面描述。

日志必须写出：

- `cmi_active`
- `reason`
- `protected` 模组 ID
- `isolated` 模组 ID
- 每个过滤器的移除数量

## 六、风险与待确认

| 风险 | 影响 | 处理建议 |
|---|---|---|
| 当前角色模组的内容由不同模组 ID 拥有 | 当前角色的部分卡牌或遗物会被误删 | 先用 MGR、Watcher 全量内容归属审计；测试当前起始牌组、三池、事件、章节 |
| 只改 `IsolatedModIds`，未改 `FilterPolicy` | 当前角色本身也可能被从角色列表移除 | 在所有过滤判定中统一检查保护集 |
| `SourceCache` 未随运行切换失效 | 切换角色模组后出现上一局残留 | 增加 `PolicyVersion`；连续运行三种角色局验证 |
| 随机角色先选幕再解析 | 第一幕可能包含其他模组章节 | 首版不纳入验收；后续单独设计 |
| 多人模式当前关闭 | 无法满足多人局 | 首版保持单人；多人需定义角色模组并集或逐玩家策略 |
| `ModelDb` 全局缓存 | 图鉴、控制台、统计可能仍显示其他模组内容 | 明确不在本局内容保证范围内；运行路径单独测试 |
| 未知归属 | 无法确定保护集 | 失败时保留当前角色内容并记录警告；不得静默把当前模组当其他模组 |
| 角色集合过滤绑定 `FilterCards` | 关闭卡片过滤时，其他角色可能仍留在 `UnlockState.Characters` | 默认分类全开时验收；若要求独立隐藏角色，需新增独立开关或把角色过滤绑定总开关 |
| 手动勾选当前模组 | 当前角色内容可能被误删 | 当前角色模组始终保护，并在设置页显示例外 |
| 选人界面隐藏其他模组 | 用户可能无法切换角色 | 首版保留全部角色可见，只在运行期隔离 |

### 未确认项

- MGR 与 Watcher 的所有卡牌、遗物、药水、事件、遭遇、章节是否都归属各自模组 ID。当前只确认两个模组被自动识别，未确认全量内容归属。
- 角色模组内容是否可能来自依赖库而不是角色模组本身。若存在，需要决定是否把依赖库视为当前模组的一部分。
- 随机角色解析后的 `RunState` 是否可稳定取得具体角色。当前代码在待定阶段明确跳过随机角色，第一幕仍需单独验证。
- 多人模式是否未来支持。当前代码明确在 `Players.Count != 1` 时停用。

## 七、测试矩阵

以下测试尚未执行。它们是施工后的验收计划。

| 场景 | 角色 | 期望 |
|---|---|---|
| 原版基线 | 摄政 | 所有角色模组内容移除；原版内容完整 |
| 单模组角色 | MGR | MGR 内容保留；没有其他角色模组内容 |
| 双模组角色 A | MGR | MGR 保留；Watcher 的卡牌、遗物、药水、事件、遭遇、章节为 0 |
| 双模组角色 B | Watcher | Watcher 保留；MGR 的卡牌、遗物、药水、事件、遭遇、章节为 0 |
| 飞溅 A | Watcher | 候选不含 MGR 卡牌；原版候选正常 |
| 飞溅 B | MGR | 候选不含 Watcher 卡牌；原版候选正常 |
| 连续运行 | 原版 → MGR → Watcher | 每次运行都重新建立过滤结果；上一局缓存不污染下一局 |
| 手动模式 | 任意模组角色 | 当前模组始终保留；其他勾选模组隔离 |
| 设置显示 | 两个角色模组 | 当前模组显示保护；另一个显示隔离 |

测试探针需要把当前仅支持强制摄政的 `AutoSlayProbe` 扩展为按角色 ID 强制 MGR、Watcher 与摄政。现有探针位置：`8.TEST/0.1.0/AutoSlayProbe/ProbeMod.cs`。

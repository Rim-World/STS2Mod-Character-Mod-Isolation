## 二、修复

本轮发现卡牌池过滤没有生效：

```csharp
PatchMethod("cards", typeof(CardPoolModel), "GetUnlockedCards", null,
    Last(typeof(PoolPatches), nameof(PoolPatches.CardPoolPostfix)));
```

最后一个参数是 `postfix`，但调用只传了五个实参，`Last(...)` 实际落在 `prefix`。前置补丁拿不到 `__result`，进入函数后立即返回，所以卡牌过滤一直没有执行。

修复为：

```csharp
PatchMethod("cards", typeof(CardPoolModel), "GetUnlockedCards", null,
    null, Last(typeof(PoolPatches), nameof(PoolPatches.CardPoolPostfix)));
```

修复后日志出现：

```text
[filter] category=cards removed=11 kept=14 reason=vanilla-run
```

这 11 张是 `MGRMod` 与 `Watcher` 放进 `TokenCardPool` 的 Token 卡，例如 `WATCHER_MIRACLE`、`MGR_MOD_CARD_FLAWED_GIRL_0`。

## 五、未闭合项

卡牌分类存在观测矛盾：

- 过滤日志明确记录 `cards removed=11 kept=14`，说明后置补丁至少在一次卡池查询中移除了 11 张 Token 卡。
- 探针在同一开局对 `TokenCardPool` 的独立二次查询仍统计到 11 张，`total=25 isolated=11`。
- 因此不能把「Token 卡池已完全清零」写成已验收；也不能把「卡牌过滤没有执行」写成事实。当前证据只能确认补丁已经执行，且实际奖励与开局后的内容日志没有模组卡。

可能原因：探针自己的直接 `GetUnlockedCards` 调用与游戏实际消费的补丁链顺序不同；此事需要单独定位。后续排查方向是给 `TokenCardPool.GetUnlockedCards` 增加前后调用编号，或直接用游戏内效果触发 Token 卡生成。

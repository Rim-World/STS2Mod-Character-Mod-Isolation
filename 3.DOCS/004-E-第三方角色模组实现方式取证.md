# 004-E 第三方角色模组实现方式取证

- 建立时间：2026-11-17 02:16
- 目的：确认第三方角色模组的内容是否带有可识别的归属信息，以及它们如何进入原版角色的内容池。

## 一、LinkuraMod：RitsuLib 角色模组样本

来源：`STS2-Reference/8.Mod-Sources/LinkuraMod`。

| 事实 | 证据 | 含义 |
|---|---|---|
| 角色用 `[RegisterCharacter]` 注册 | `core/characters/kaho/HinoshitaKaho.cs:10-11` | 内容类型在模组程序集 |
| 卡牌用 `[RegisterCard(typeof(HinoshitaKahoCardPool), Inherit = true)]` 注册 | `core/cards/kaho/KahoCard.cs:7-9` | 卡牌进入角色专属卡池 |
| 角色继承 `ModCharacterTemplate<TCardPool, TRelicPool, TPotionPool>` | `core/characters/LinkuraCharacterModel.cs:24-30` | 三个池由角色模板绑定 |
| 清单声明 RitsuLib 依赖，`min_game_version` 为 0.107.1 | `mod_manifest.json:6-16` | 角色模组常见依赖形态 |
| 角色模板的 `CardPool`/`RelicPool`/`PotionPool` 是 sealed，直接取注册模型 | RitsuLib `src/Scaffolding/Characters/ModCharacterTemplate.cs:376-391` | 池与角色强绑定 |
| 初始牌组/遗物/药水由模板解析注册内容 | 同上 `:394-400` | 角色局内容完整 |

结论：角色模组的内容类型来自模组程序集；角色 → 三个池 → 内容类型的关系明确。按类型程序集归属过滤是可行的。

## 二、BaseLib：内容注册与后置追加

来源：`STS2-Reference/8.Mod-Sources/BaseLib-StS2`。

| 事实 | 证据 | 含义 |
|---|---|---|
| `CustomContentDictionary.AddModel` 调 `ModHelper.AddModelToPool` | `Patches/Content/ContentPatches.cs:55-68` | 卡牌/遗物/药水进入池 |
| 自定义角色后置追加到 `ModelDb.AllCharacters` | `ContentPatches.cs:151-159` | 角色出现在选人界面 |
| 自定义先古前置换入 `_sharedAncientSubset` | `ContentPatches.cs:189-215` | 先古过滤需要处理该字段 |
| 共享事件后置追加 | `ContentPatches.cs:293-313` | 事件过滤需要覆盖共享列表 |
| 自定义章节追加到 `ModelDb.Acts` | `ContentPatches.cs:315-340` | 章节过滤需要覆盖 ActsByIndex |

BaseLib 不提供类型 → 模组 ID 的通用注册表；类型程序集归属是主要依据。BaseLib 的 `WhatMod` 工具也按程序集与根命名空间反查模组，说明该思路在生态内已有先例。

## 三、RitsuLib：内容注册表与动态章节补丁

来源：`STS2-Reference/8.Mod-Sources/STS2-RitsuLib-v0.6.13`。

| 事实 | 证据 | 含义 |
|---|---|---|
| `ModContentRegistry.TryGetOwnerModId(Type, out string)` | `src/Content/ModContentRegistry.cs:120-128` | 可直接查询精确归属 |
| 注册内容按模组 ID 分区 | `ModContentRegistry` 的 `Registries`、`ModId` | 适合做精确归属 |
| 角色后置追加 `ModelDb.AllCharacters` | `src/Content/Patches/ModelDbContentPatches.cs:12-33` | 选人界面可见 |
| 动态补丁每个具体章节的 `AllEvents`/`AllAncients`/`GenerateAllEncounters`/`GetUnlockedAncients` | `src/Content/DynamicActContentPatcher.cs:189-225` | 过滤必须排在这些后置之后 |
| 章节随机列表默认排除未声明 opt-in 的模组章节 | `src/Content/Patches/ModelDbContentPatches.cs:94-145` | 部分章节隔离已由框架完成 |

结论：

- 若模组用 RitsuLib 注册，可直接查 owner；这是最精确的归属来源。
- 若模组不用 RitsuLib，仍可用类型所在程序集反查 `ModManager` 的模组程序集列表。
- 两者都失败时，未知非游戏程序集按未知归属处理，不自动隔离；用户可切换到手动选择模式并记录日志。

### 角色模组识别的直接证据

| 事实 | 证据 | 含义 |
|---|---|---|
| BaseLib 自定义角色构造时加入内容字典 | `7.Mod-Sources/BaseLib-StS2/Abstracts/CustomCharacterModel.cs:25-28` | 角色类实例化即可被追踪 |
| BaseLib 把自定义角色追加到 `ModelDb.AllCharacters` | `7.Mod-Sources/BaseLib-StS2/Patches/Content/ContentPatches.cs:151-158` | 注册后的角色出现在统一角色列表 |
| RitsuLib 把注册角色追加到 `ModelDb.AllCharacters` | `7.Mod-Sources/STS2-RitsuLib-v0.6.13/src/Content/Patches/ModelDbContentPatches.cs:12-33` | 角色注册表与游戏角色列表对齐 |

因此，自动识别可以以 `ModelDb.AllCharacters` 为主要证据：
非游戏程序集角色 → 反查模组 → 该模组是角色模组。未注册角色类只作为补充证据。

## 四、已安装模组清单的观察

当前游戏 `mods/` 目录中的模组主要是：

- 原版卡牌替换/回调（CorpseExplosion、Reaper、Evolve、Scavenge 等）；
- 遗物池修改（DarvRelicPoolMod）；
- 界面/计数（JugglingCounter）；
- 棱彩宝石过滤（PrismaticGemFilter）。

这些不是完整角色模组。`mods（备份猎人和塔1鸡煲皮肤mod）` 中的包是皮肤/贴图型 PCK，带少量 DLL；不是完整角色内容样本。因此本报告的角色模组实现证据主要来自参考库中的 LinkuraMod 源码与 BaseLib/RitsuLib。

## 五、对隔离方案的含义

1. 标准角色模组的内容类型在模组程序集；按类型 → 程序集 → 模组映射可以识别。
2. 角色模组的卡牌/遗物/药水通过 `ModHelper` 进入池；过滤池查询出口可以移除。
3. 角色模组的事件/遭遇/先古/章节通过 BaseLib/RitsuLib 的 Harmony 后置追加；过滤必须排在后置之后，或用消费端兜底。
4. 不依赖具体模组 ID：新增模组只要走标准注册，就自动被识别。
5. 不能识别的情况：模组把内容类型编译进游戏程序集（不可能）、用动态类型（罕见）、或绕过池直接注入奖励（补丁型）。
